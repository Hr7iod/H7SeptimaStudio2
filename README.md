# H7 Септима

Репозиторий: [Hr7iod/H7SeptimaStudio2](https://github.com/Hr7iod/H7SeptimaStudio2). Основная ветка — `master`.

Адаптивный сайт студии индивидуальной разработки и поддержки сайтов для малого и среднего бизнеса.

## Запуск

Node.js 22 или новее. Для локального сервера зависимости не нужны.

```powershell
npm run dev
```

Открыть http://127.0.0.1:4173. Готовые файлы сайта находятся в `dist`; сборка не требуется.

## Поведение

- Навигация и FAQ работают без JavaScript.
- Переключатель задачи меняет пояснение и записывает выбор в бриф.
- Бриф проверяет поля и скачивается в UTF-8 на устройство посетителя. Данные не отправляются и не сохраняются на сервере. На странице это указано явно.
- Отправка заявок ещё не подключена: сначала нужен реальный контакт студии или серверный обработчик. Форма не сообщает об успешной отправке.

## Дизайн Cobalt и Vantage

Мини-студия удалена по просьбе пользователя, включая настройки дизайна в брифе. Остались выбор задачи, FAQ, мобильное меню и скачивание брифа.

От Vantage: сине-чёрная поверхность, Geologica и точечный знак H7. От Cobalt: холодные светлые разделы, тонкие линии, синие акценты и кнопки с нижней гранью. Прежний логотип H7 в синей плашке сохранён. Фотографии не используются.

Скрипт point-field.js строит облако из существующей геометрии логотипа, не изображает вымышленные сканы или показатели. При наведении мягкая градиентная подсветка следует за указателем по обеим осям; курсор не смещает точки. Плавное покачивание H7 ускорено в 3,25 раза: полный цикл занимает около 25 секунд. Цвет, яркость и размер точек меняются непрерывно, без резкой границы подсветки. После ухода мыши возвращается автоматический проход подсветки. Кнопки паузы нет; наведение и фокус не останавливают движение. Анимация останавливается вне экрана и при скрытии вкладки. При prefers-reduced-motion показывается статичный кадр; без JavaScript виден SVG-знак. Локальные шрифты Geologica и Golos Text снабжены лицензиями в dist/fonts.

Для проверки браузером нужен установленный Chrome; сервер должен работать. В `scripts/verify.mjs` можно задать `CHROME_PATH` и `SITE_URL`.

## Автоматическая публикация

Workflow `.github/workflows/deploy.yml` запускается при пуше в `master`, при pull request в `master` и вручную через Actions. Проверяет JavaScript, синтаксис скрипта деплоя и наличие `dist/index.html`. Сборка и установка зависимостей для публикации не нужны: сайт готов к раздаче из `dist`.

После успешных проверок пуш в `master` публикует содержимое `dist/` на сервер по SSH через `rsync`. Ручной запуск публикует только выбранную ветку `master`. Pull request выполняет только проверки. Запуски не прерывают уже начатый деплой.

Продакшен: `92.118.91.15`, домен `h7septima.ru`, каталог `/var/www/h7septima.ru/html`. Деплой выполняет отдельный пользователь `h7deploy`, без `sudo`. Файлы, настройки и службы существующего сайта `putniq.ru` не используются. Конфигурация нового виртуального хоста находится в `ops/nginx/h7septima.conf`.

Если обязательных настроек нет, проверки проходят, а задача `Publish to production` пропускается. В отчёте Actions перечислены недостающие настройки.

В GitHub → Settings → Secrets and variables → Actions добавьте **Repository secrets**:

- `SSH_HOST` — имя сервера или IPv4-адрес.
- `SSH_USER` — пользователь для публикации.
- `SSH_PRIVATE_KEY` — отдельный приватный SSH-ключ без парольной фразы. Публичная часть должна быть в `~/.ssh/authorized_keys` этого пользователя на сервере.
- `SSH_KNOWN_HOSTS` — проверенная запись ключа сервера из `known_hosts`. Для нестандартного порта запись должна использовать `[host]:port`. Перед сохранением сверьте отпечаток с сервером; workflow использует строгую проверку ключа.

Там же добавьте **Repository variables**:

- `DEPLOY_PATH` — обязательный абсолютный путь к отдельной папке сайта, например `/var/www/example.com/html`. Допустимы латинские буквы, цифры, `_`, `-`, `.`, `/`, без пробелов.
- `SSH_PORT` — необязательный SSH-порт; по умолчанию `22`.
- `PRODUCTION_URL` — необязательный полный адрес сайта, например `https://example.com`. Если указан, после загрузки выполняется HTTP-проверка; ошибка делает деплой неуспешным.
- `PRODUCTION_RESOLVE` — необязательное правило `curl --resolve`. На этом сервере задано `h7septima.ru:80:92.118.91.15`: HTTP-проверка обращается к нужному серверу с правильным доменом, даже пока публичный DNS указывает на старый IP.

Настройки нужно добавлять на уровне репозитория: проверка готовности выполняется до входа в environment `production`. Сам деплой отмечается в этом environment.

На Linux-сервере должны быть установлены SSH, `rsync` и `realpath`, папка `DEPLOY_PATH` должна существовать и быть доступна пользователю на запись. Веб-сервер должен раздавать эту папку; Node.js на продакшене не требуется. Для обновления статических файлов перезагрузка Nginx не нужна.

### DNS и HTTPS

Для перехода на новый сервер у регистратора задайте A-запись `h7septima.ru` → `92.118.91.15`. Для `www` можно добавить CNAME → `h7septima.ru`. Устаревшие AAAA-записи нужно убрать, если IPv6 нового сервера не настраивается.

До смены DNS сайт проверяется так:

```bash
curl --resolve h7septima.ru:80:92.118.91.15 http://h7septima.ru/
```

После обновления DNS нужно выпустить отдельный TLS-сертификат для H7 и включить HTTPS в его виртуальном хосте. Затем обновить `PRODUCTION_URL` на `https://h7septima.ru` и `PRODUCTION_RESOLVE` на `h7septima.ru:443:92.118.91.15`. Сертификаты и конфигурация `putniq.ru` при этом не используются.

Синхронизация удаляет из папки сайта файлы, которых нет в `dist/`, сохраняя `.well-known/` для проверки домена и сертификатов. Используйте отдельную папку без загрузок пользователей и других данных. Секреты и ключи не хранятся в Git. Скрипт деплоя: `scripts/deploy.sh`.

Прежняя конфигурация Sites сохранена в `.openai/hosting.json`; GitHub Actions её не использует.
