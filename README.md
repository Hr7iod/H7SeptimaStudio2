# H7 Септима

Репозиторий: [Hr7iod/H7SeptimaStudio2](https://github.com/Hr7iod/H7SeptimaStudio2). Основная ветка — `master`.

Адаптивный сайт студии индивидуальной разработки и поддержки сайтов для малого и среднего бизнеса.

## Запуск

Node.js 22 или новее. Для почтового обработчика нужен Python 3.10 или новее, без сторонних зависимостей.

```powershell
npm run dev
```

Открыть http://127.0.0.1:4173. Готовые файлы сайта находятся в `dist`; сборка не требуется.

Для отправки писем скопируйте `.env.example` в `.env`, заполните `SMTP_PASSWORD` паролем приложения Яндекса с доступом к почте и запустите во втором терминале `npm run dev:mail`. Статический сервер передаёт `/api/brief` обработчику на `127.0.0.1:4174`. Обычный пароль аккаунта не нужен. `.env` исключён из Git; его нельзя помещать в `dist`.

## Поведение

- Навигация и FAQ работают без JavaScript.
- Переключатель задачи меняет пояснение на странице. Его выбор не добавляется в заявку.
- Заявка отправляется на `dmitrii@h7septima.ru` через SMTP Яндекса с TLS. В письмо входят только имя, контакт и описание проекта. Контакт принимается в свободном формате: почта, телефон, мессенджер или другой способ связи. Для адреса почты добавляется `Reply-To`; остальные контакты остаются в тексте письма. Проверки формата контакта нет, только обязательное заполнение и ограничение длины.
- Имя, контакт и описание обязательны. Форма сохраняет текст при ошибке, блокирует повторное нажатие на время отправки и очищается только после подтверждения SMTP-сервера. Подтверждение означает приём письма почтовым сервером; доставку во входящие следует проверить в ящике.
- Обработчик проверяет поля повторно, ограничивает размер запроса до 16 КБ и частоту до пяти попыток за десять минут с одного IP, использует скрытое поле против ботов и проверяет Origin. Тексты заявок, контакты и SMTP-пароли не записываются в журналы приложения и не сохраняются в отдельную базу.
- Для прямых писем, в том числе без JavaScript и при ошибках отправки формы, указан `info@h7septima.ru`. Получатель заявок и SMTP-отправитель остаются `dmitrii@h7septima.ru`.

## Дизайн Cobalt и Vantage

Мини-студия удалена по просьбе пользователя, включая настройки дизайна в брифе. Остались выбор задачи, FAQ, мобильное меню и форма заявки.

От Vantage: сине-чёрная поверхность, Geologica и точечный знак H7. От Cobalt: холодные светлые разделы, тонкие линии, синие акценты и кнопки с нижней гранью. Прежний логотип H7 в синей плашке сохранён. Фотографии не используются.

Скрипт point-field.js строит облако из существующей геометрии логотипа, не изображает вымышленные сканы или показатели. При наведении мягкая градиентная подсветка следует за указателем по обеим осям; курсор не смещает точки. Плавное покачивание H7 ускорено в 3,25 раза: полный цикл занимает около 25 секунд. Цвет, яркость и размер точек меняются непрерывно, без резкой границы подсветки. После ухода мыши возвращается автоматический проход подсветки. Кнопки паузы нет; наведение и фокус не останавливают движение. Анимация останавливается вне экрана и при скрытии вкладки. При prefers-reduced-motion показывается статичный кадр; без JavaScript виден SVG-знак. Локальные шрифты Geologica и Golos Text снабжены лицензиями в dist/fonts.

## Автоматическая публикация

Workflow `.github/workflows/deploy.yml` запускается при пуше в `master`, при pull request в `master` и вручную через Actions. Проверяет JavaScript, тесты почтового обработчика, синтаксис скрипта деплоя и наличие `dist/index.html`. Сборка и установка зависимостей для публикации не нужны.

После успешных проверок пуш в `master` обновляет `server/brief.py` в `/opt/h7septima-brief`, перезапускает почтовый обработчик и публикует содержимое `dist/` на сервер по SSH через `rsync`. Ручной запуск публикует только выбранную ветку `master`. Pull request выполняет только проверки. Запуски не прерывают уже начатый деплой.

Продакшен: [https://h7septima.ru](https://h7septima.ru), сервер `92.118.91.15`, каталог `/var/www/h7septima.ru/html`. Деплой выполняет отдельный пользователь `h7deploy`, без `sudo`. Файлы, настройки и службы существующего сайта `putniq.ru` не используются. Конфигурация нового виртуального хоста находится в `ops/nginx/h7septima.conf`.

Если обязательных настроек нет, проверки проходят, а задача `Publish to production` пропускается. В отчёте Actions перечислены недостающие настройки.

В GitHub → Settings → Secrets and variables → Actions добавьте **Repository secrets**:

- `SSH_HOST` — имя сервера или IPv4-адрес.
- `SSH_USER` — пользователь для публикации.
- `SSH_PRIVATE_KEY` — отдельный приватный SSH-ключ без парольной фразы. Публичная часть должна быть в `~/.ssh/authorized_keys` этого пользователя на сервере.
- `SSH_KNOWN_HOSTS` — проверенная запись ключа сервера из `known_hosts`. Для нестандартного порта запись должна использовать `[host]:port`. Перед сохранением сверьте отпечаток с сервером; workflow использует строгую проверку ключа.

Там же добавьте **Repository variables**:

- `DEPLOY_PATH` — обязательный абсолютный путь к отдельной папке сайта, например `/var/www/example.com/html`. Допустимы латинские буквы, цифры, `_`, `-`, `.`, `/`, без пробелов.
- `SSH_PORT` — необязательный SSH-порт; по умолчанию `22`.
- `PRODUCTION_URL` — необязательный полный адрес сайта, например `https://example.com`. Если указан, после загрузки выполняется HTTP-проверка; ошибка делает деплой неуспешным.
- `PRODUCTION_RESOLVE` — необязательное правило `curl --resolve`. На этом сервере задано `h7septima.ru:443:92.118.91.15`: HTTPS-проверка обращается к нужному серверу с правильным доменом и проверяет TLS-сертификат независимо от DNS-кеша runner.

Настройки нужно добавлять на уровне репозитория: проверка готовности выполняется до входа в environment `production`. Сам деплой отмечается в этом environment.

На Linux-сервере должны быть установлены SSH, `rsync`, `realpath` и Python 3.10+. Папки `DEPLOY_PATH` и `/opt/h7septima-brief` должны существовать и быть доступны пользователю публикации на запись. Веб-сервер раздаёт `DEPLOY_PATH`; Node.js на продакшене не требуется. Для обновления статических файлов перезагрузка Nginx не нужна.

### Почтовый обработчик на сервере

Исходник: `server/brief.py`. Отдельная служба `h7septima-brief.service` работает пользователем `h7brief` и слушает только `127.0.0.1:4174`; Nginx передаёт ей точный путь `/api/brief`. Остальные сайты и службы сервера не используются.

Первичная настройка от root:

```bash
useradd --system --user-group --no-create-home --shell /usr/sbin/nologin h7brief
install -d -m 755 -o h7deploy -g h7deploy /opt/h7septima-brief
install -m 644 -o h7deploy -g h7deploy server/brief.py /opt/h7septima-brief/brief.py
install -d -m 700 /etc/h7septima
install -m 600 .env /etc/h7septima/brief.env
install -m 644 ops/systemd/h7septima-brief.service /etc/systemd/system/h7septima-brief.service
install -m 440 ops/systemd/h7septima-brief.sudoers /etc/sudoers.d/h7septima-brief
visudo -cf /etc/sudoers.d/h7septima-brief
systemctl daemon-reload
systemctl enable --now h7septima-brief.service
```

Затем добавьте блок `location = /api/brief` из `ops/nginx/h7septima.conf` в отдельный HTTPS-хост H7, выполните `nginx -t` и `systemctl reload nginx`. Для `h7deploy` разрешён только перезапуск этой службы, без произвольного `sudo`. Пароль хранится в `/etc/h7septima/brief.env` с правами `600`, вне сайта и каталога публикации. При изменении пароля перезапустите службу. `ALLOWED_ORIGINS` должен содержать фактический адрес формы, `MAIL_TO` задаёт единственного получателя на сервере.

Верификация: `npm run test:mail` проверяет UTF-8 письма, фиксированного получателя, Reply-To, ошибки SMTP, ограничения запросов и валидацию. `node scripts/verify.mjs` проверяет форму в браузере с подменой ответов API, без реальных писем. Для проверки доставки нужна одна явно обозначенная тестовая заявка через рабочую форму.

### DNS и HTTPS

A-запись `h7septima.ru` направлена на `92.118.91.15`. Для основного домена настроен отдельный сертификат Let's Encrypt и перенаправление с HTTP на HTTPS. В GitHub заданы `PRODUCTION_URL=https://h7septima.ru` и `PRODUCTION_RESOLVE=h7septima.ru:443:92.118.91.15`.

Проверка с обходом DNS-кеша:

```bash
curl --resolve h7septima.ru:443:92.118.91.15 https://h7septima.ru/
```

Сертификат выпущен через `certbot certonly --webroot -w /var/www/h7septima.ru/html --cert-name h7septima.ru -d h7septima.ru`, без автоматического редактирования других виртуальных хостов. Продлением управляет существующий `certbot.timer`. Для этого сертификата задан отдельный deploy-hook `/usr/local/sbin/h7septima-reload-nginx`, исходник — `ops/certbot/reload-h7septima.sh`; после продления он проверяет конфигурацию и плавно перечитывает её в Nginx. Путь `/.well-known/acme-challenge/` доступен по HTTP для автоматического продления и сохраняется при деплое.

`www.h7septima.ru` пока указывает на прежний сервер и не включён в сертификат. Для его подключения нужно изменить DNS (например, CNAME → `h7septima.ru`), добавить `www.h7septima.ru` в сертификат и HTTPS-виртуальный хост. Сертификат, виртуальный хост и настройки продления `putniq.ru` остаются отдельными.

Синхронизация удаляет из папки сайта файлы, которых нет в `dist/`, сохраняя `.well-known/` для проверки домена и сертификатов. Используйте отдельную папку без загрузок пользователей и других данных. Секреты и ключи не хранятся в Git. Скрипт деплоя: `scripts/deploy.sh`.

Прежняя конфигурация Sites сохранена в `.openai/hosting.json`; GitHub Actions её не использует.
